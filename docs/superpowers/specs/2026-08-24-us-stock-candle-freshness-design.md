# US-Stock Candle Freshness and Reliable Pages Publication Design

## Goal

Ensure every scheduled or manual scanner run can publish new US-stock candles, make a green action prove the new site is actually served, and expose stale market data without hiding affected symbols.

## Root Cause

Scheduled and manual runs repeatedly deploy from the same `main` commit. `actions/deploy-pages@v4` uses `GITHUB_SHA` as the Pages build version, and repeated same-version deployments can report success while the previous artifact remains served.

The scanner also accepts any non-empty Yahoo series without comparing its final timestamp with peer symbols. The combined report then displays the maximum timestamp across all markets, allowing crypto or Vietnam data to hide stale US data.

## Publication Design

The workflow keeps the existing native GitHub Pages actions and adds one lightweight trigger branch:

1. A scheduled or manually dispatched run creates a new timestamp commit on `scanner-trigger`, based on the current `main` tree.
2. The trigger run dispatches the workflow at `scanner-trigger` after pushing. (`GITHUB_TOKEN` pushes do not start workflows.) The dispatched run uses the unique trigger commit as `GITHUB_SHA`, so `deploy-pages` receives a new build version.
3. A direct push to `main` continues to launch the real scan immediately.
4. Schedule and manual runs do not scan themselves; they only create the trigger commit.
5. The existing `scanner-state` branch remains dedicated to compact watchlist state.

The site artifact includes a small `deployment.json` containing the current Actions run ID and SHA. After `deploy-pages`, the workflow polls the published marker for up to twelve minutes. The deploy job fails if the served run ID never matches, preventing false-green deployments.

## Freshness Design

The scanner keeps the live Yahoo D1 candle during US trading hours, as requested. It no longer calls that candle closed.

For each market, the scanner finds the latest timestamp returned across that market's symbols. A symbol behind its market timestamp remains in the report and receives a warning containing:

- Its own latest timestamp.
- The market's latest timestamp.
- A stale status and readable warning message.

The combined payload includes `data_as_of_by_market` and `data_warnings_by_market`. The report header renders the per-market timestamps, including stale-symbol counts, so a fresh crypto candle cannot mask stale US-stock data. Individual result cards retain their exact `data_as_of` and show their warning when applicable.

This peer comparison deliberately avoids a new exchange-calendar dependency. Publication verification catches the whole-site stale-artifact failure; peer comparison catches isolated stale symbols such as EA.

## Live Candle Semantics

Yahoo's current-day D1 bar remains part of pattern detection and chart rendering. Text that currently says “latest closed candle” changes to “latest candle,” which is correct for both live and completed bars. No synthetic intraday aggregation or market-hours calendar is added.

## Error Handling

- Failure to create the trigger commit fails the trigger run.
- Failure to download, combine, upload, or deploy remains fatal as today.
- Failure to observe the new `deployment.json` after publication fails the deploy job.
- An isolated stale symbol remains visible and does not fail the scan.
- A stale market is explicit through its per-market timestamp and warnings rather than hidden by the global maximum.

## Testing

Automated tests verify:

- Scheduled/manual events create a unique `scanner-trigger` commit and skip scanning in the trigger run.
- Push events run the scan and deploy jobs.
- The workflow writes and verifies `deployment.json` after Pages deployment.
- Stale peer symbols receive warnings while remaining present.
- Per-market latest timestamps and stale-symbol summaries are included in result payloads.
- Report HTML displays per-market freshness and individual stale warnings.
- Trigger-volume evidence no longer claims the latest D1 bar is closed.
- Existing scanner, report, workflow, and full-suite tests remain green.

## Acceptance Criteria

- A scheduled or manual refresh deploys with a unique Pages build version even when `main` has not changed.
- A successful action guarantees the matching run marker is served publicly.
- The public US-stock report advances to the Yahoo timestamp generated by the scan.
- US live D1 bars remain usable during the session.
- An isolated stale symbol remains visible with a warning.
- The report exposes a separate data timestamp for every represented market.
